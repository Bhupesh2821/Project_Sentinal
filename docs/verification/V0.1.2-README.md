# SENTINAL — MARK-007
## V0.1.2 · Explicit cameras, network CCTV and expanded categories

SENTINAL is a native macOS monitoring prototype with real local pretrained object detection and ByteTrack association. It accepts videos selected at runtime, the Mac's camera and compatible RTSP/RTSPS/HTTP/HTTPS video feeds. It has no facial recognition, identity lookup, threat scoring or unattended-baggage alert system.

### Open and use the application

Open **launch.command** in Finder. In Terminal you can run `zsh launch.command` from this folder. The existing local environment and model are installed. Nothing starts the camera automatically, and detection metadata recording is unchecked at every launch.

**Your own videos:** click **Import & analyze video…** or drop one local video onto SENTINAL. You can do this while another source is running. A background importer copies the file into `data/videos`, validates decoding and reports progress. Once ready, SENTINAL stops the previous source, creates a fresh tracking session and analyzes the new video. The application and model stay loaded. Importing another file repeats this flow without restarting the app. Previously imported videos are available in the library selector. Pause, Resume and the position slider apply to local videos. Seeking creates a new session because old track IDs are not valid across a discontinuity.

Imports preserve the original file and copy the whole file, including any audio already present; SENTINAL does not capture microphone audio or play video sound. Full SHA256 hashing prevents persistent duplicate imports. Large files are copied in bounded chunks, with a 256 MB free-space margin. Cancellation and failures clean up incomplete copies. Codec support depends on OpenCV's installed decoder: common MP4, MOV, MKV, AVI and WebM files can be selected, but every possible codec/container is not guaranteed. Unsupported, empty, incomplete or damaged files produce a readable error. Cancellation is cooperative and waits for the current file/decoder operation to return.

**Mac / iPhone camera:** choose **Camera**, select the exact named device and press **Start monitoring**. Stop before choosing another. The initial selection prefers an available built-in Mac camera. Capture resolves its stable device identity, so changes in device order cannot open a different camera. If the chosen camera disappears, monitoring reports an error and requires explicit reselection. Refresh lists devices without opening them. Compatible iPhones appear through Apple Continuity Camera; see [camera and CCTV setup](docs/CAMERA_NETWORK_SETUP.md).

**Network CCTV:** choose **Network camera**. Click **Find / connect CCTV…** to discover ONVIF cameras on the active local network, or enter a manual ONVIF device-service address. Enter its account, click **Get video streams**, choose a profile and **Use selected stream**. This fills the controls; press **Start monitoring** explicitly. You can also enter a live RTSP/RTSPS/HTTP/HTTPS endpoint directly with optional credentials. Use an endpoint provided by your camera/NVR, rather than a normal webpage or share link. Credentials stay in memory; they are not saved in settings or detection metadata. Labels and errors omit URL credentials, path and query. Pasted user information is moved into the masked credential controls. Changing the endpoint clears old credentials. Live sources cannot seek or pause.

A dropped established network feed receives up to three consecutive reconnect attempts by default. Reconnection resets tracking and creates a new session UUID. An unavailable initial connection shows an error so you can correct the address and retry. No invented replacement stream is displayed.

### Monitoring controls and measurements

Boxes, labels/confidence and IDs have independent switches. The confidence control filters displayed results after ByteTrack receives low-score candidates. Its own new-track thresholds remain independent of the presentation slider. Select the model while stopped, then choose all permitted object categories, people/bags, or safety equipment/tools. Everyday objects uses YOLO11n (80 COCO categories). The two extended model options add an Open Images catalog (lightweight YOLOv8n and higher-capacity YOLOv8s; only one is loaded at a time); Browse supported categories searches exact supported labels without loading weights. Human age/gender/body-part and weapon categories in the broader model are excluded from reported detections and the catalog. Category support does not establish accuracy on your footage: see VERIFICATION_REPORT.md for measured successes and misses. Generic helmet/glove/boot labels do not establish protective rating, proper use or compliance. High-visibility vests and fire extinguishers are not claimed. The inference-size selector changes processing size without reloading the model. Smaller inputs can be faster but miss small bags.

Live capture runs in an isolated process with a fixed shared-memory newest-frame slot. Superseded capture frames are skipped to reduce local buffering; they are not silently counted as analyzed frames. The dashboard reports the actual skip count and local frame age through completed analysis. That age excludes upstream camera encoding/network buffers and later GUI painting. Live frames with a longer edge above 1920 are downscaled before delivery; boxes refer to the returned/displayed frame pixels. Local files retain decoded source dimensions and are processed sequentially unless you seek.

**Pipeline FPS** is measured capture/wait + detection + tracking processing throughput. For local files it excludes deliberate playback waits and GUI painting, so it can exceed displayed playback rate. File playback uses decoder media-time differences when available, with average-FPS fallback; slow inference slows playback without fabricating frames. **Vision latency** includes model preprocessing, inference, postprocessing and tracking, with MPS synchronization. There is no invented GPU utilization reading or fixed FPS promise.

Heavy library imports run before the window appears. A cold startup or first inference can take several seconds. The selected model stays loaded across sessions. Changing models while stopped replaces it at the next Start; switching cameras/files with the same model reuses it. `auto` prefers MPS when available and an operation failure retries using CPU. Stop/quit cooperates with inference; a stuck live capture child can be terminated and its shared buffer released without force-terminating the Qt inference thread.

### Privacy and storage

Inference is local and uses no paid AI API. Network feeds require access to the selected server; receiving their video is intentional network input. SENTINAL does not send camera/video frames to cloud inference services. Runtime Ultralytics online checks, telemetry sync and auto-install are disabled. Only explicit installation downloads dependencies/weights. Discovery sends bounded local ONVIF probes only when clicked; profile lookup contacts the selected device. Neither transmits footage.

The imported-video library always stores local file metadata such as filename, hash, size and geometry; it stores no detections. Imported files remain until you remove them. They are separate from optional detection recording.

When explicitly enabled, `recordings/detections.sqlite3` samples detection snapshots no more often than every two wall-clock seconds by default. Rows include UTC time, source/session, frame/media position, class/confidence, optional track ID, box coordinates, processing FPS, latency and backend. Each session also records its model filename because class IDs differ between models. Existing databases gain this column without discarding earlier rows. Source labels for network feeds omit credentials/path/query. A write failure disables metadata recording and leaves video analysis running. Pruning runs on database open and sampled writes: seven days and 100,000 newest rows by default. No cleanup runs while the application is closed. SQLite may retain freed pages; this is not secure erasure. Close the app before manually removing database/WAL/SHM files. Diagnostic logs rotate at 2 MB with three backups and contain errors, not footage.

### Configuration and fresh installation

Edit `config/settings.json` and relaunch for capture dimensions, model path, default size/device, metadata sampling/retention and network timeouts/retry limits. Normal default capture is 640×480, inference size 640, confidence .25, open timeout 5 s, fresh-frame timeout 2 s and three retries separated by 1 s. Unsupported settings fail early. `zsh launch.command --device cpu` forces CPU. `--video /absolute/path/video.mp4` preselects a file without starting it; ordinary GUI import handles project-local copying.

For a fresh machine/copy, install Apple Silicon Python **3.12**, then run `install.command` once and `launch.command`. The pinned stack was verified with Python 3.12.15 on macOS 26.6.2, Apple M4 and 16 GB RAM. Its PyTorch/Qt wheels require macOS 14 or later. Python 3.11 is an unverified alternative; Python 3.14 is not the tested environment. Paths with spaces are supported. All project scripts source runtime-env.sh before Python, keeping temp/cache files local. No separate backend service is needed. The local HTTP feed used in tests is a verifier fixture, not a required application service.

YOLO11n is a lightweight 2.6M-parameter COCO detector; the loaded model must expose person (0), backpack (24), handbag (26), suitcase (28). All classes are in docs/MODEL_CLASSES.json. It uses Ultralytics' supported tracking interface with ByteTrack, conf=.05 candidate input and NMS IoU=.7. Class support does not promise a detection in every scene, and COCO detection is not a specialized firearm detector. See LICENSE_NOTES.md, the [official YOLO11 documentation](https://docs.ultralytics.com/models/yolo11/) and [OpenCV capture documentation](https://docs.opencv.org/4.x/d8/dfe/classcv_1_1VideoCapture.html).

### Tests, architecture and remaining acceptance

Run `zsh test.command -q` for the full suite including actual recorded-video inference. Test artifacts stay under work/. Component tests use explicit fakes/synthetic codec inputs; those do not prove model accuracy or hardware access. Native acceptance tools include tools/verify_exact_cameras.py, tools/verify_v112_desktop.py, tools/verify_safety_tools.py, tools/verify_real_inputs.py and tools/verify_live_soak.py. They must be run intentionally; the camera tools activate the camera without saving images.

The root VERIFICATION_REPORT.md and docs/evidence/ contain dated measurements and distinguish actual hardware, recorded footage, real network transport and mocked tests. New input verification is recorded separately from the original V0.1 measurements. Physical IP-camera compatibility still needs your actual camera endpoint; a successful local HTTP MJPEG connection cannot prove every RTSP device, NVR, codec or network. Private user footage has not been accuracy-labelled in advance: choose it dynamically in the application.

Detection, tracking, file/network decoding and data contracts operate independently of the desktop UI and SQLite. The macOS exact-device camera adapter uses Qt Multimedia in its isolated capture process, without a desktop window. Other platforms can retain a suitable platform capture adapter. It provides validated observations, source lifecycle, detector/tracker, measured performance and VisionPipeline. The desktop worker owns inference and metadata, communicates through a bounded command queue and newest-packet mailbox, and supports file pause/seek. A separate importer performs file copying/hash/probe work. Tracking keys combine session UUID and numeric ID. File switches, seeks and reconnects reset associations; resolution changes preserve source-coordinate geometry. Future BAGWATCH integration is documented in docs/FUTURE_UPGRADES.md and is not implemented here.

Small/distant objects, low light, crowding, similar objects, fast motion and occlusion can cause misses or ID changes. A one-minute stability observation is not proof of indefinite leak-free or thermal operation. There is no cross-camera identity, owner association or incident decision system. A signed standalone .app remains a future packaging task.
