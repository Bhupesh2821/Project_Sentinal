## Implementation delivered

The preserved camera/file/network adapters feed one VisionPipeline. Real specialized models run in the inference worker, separately from ordinary COCO/OpenImages outputs. Every hazard observation carries actual confidence, source-pixel coordinates, optional model-specific tracking ID and pinned model provenance. Models remain loaded across same-model source changes; thresholds/resolution configure the existing suite. Restricted checkpoint loading, checksums and exact class maps reject unknown/altered specialized assets. No runtime downloads, generated detections or embedded prediction overlays are used.

Fresh observations reach a bounded incident worker and temporal engine. Confidence, consecutive samples, persistence, maximum gap, overlap/tracking association, duplicate suppression and cooldown are configurable, including camera/source overrides. Category severity is separate from confidence. Alerts are explicitly POSSIBLE, with operator acknowledgment/verification/dismissal/closure. Audio/desktop notifications, incident recording, evidence and legacy detection metadata start off. SQLite review/audit and snapshots work when opted in. Storage errors remain visible and do not suppress an uncertain visual alert.

The dashboard preserves exact Mac/iPhone selection, dynamic import/drop/pause/seek/replay, ONVIF and direct RTSP/HTTP sources, ordinary detection/tracking and the searchable577-category catalog. The new Operator center provides incident filters/review, camera health, model/rule controls and actual diagnostics. Inactive states immediately clear live statistics and mark retained measurements historical. Optional GHS controls are disabled and clearly unavailable.

Named cameras resolve exact local identities or authorized network endpoints. Full URLs/passwords stay in memory by default; explicit persistence uses macOS Keychain. The registry contains metadata/health without complete endpoints/passwords. No unrelated network scan or authentication bypass is implemented.

## Privacy, storage and operator safeguards

Camera activation requires an explicit user monitoring session. Local file imports are deliberate managed copies; no microphone recording, facial identification, individual profiling, intent inference or automatic accusation is performed. Routine video inference does not transmit footage or require an AI account/API. Normal operation is offline after installation; connecting an authorized network stream is an explicit source selection.

Incident recording, snapshots, ordinary detection metadata, sound and desktop output start off. Default incident retention is7days/max10,000incidents; evidence has size/count/age limits, with deletion controls. Retention runs when the service/store is used, not through an always-running system service. User-imported videos are not automatically deleted. Snapshot storage is owner-only plaintext with SHA256 integrity checks. The access boundary is the local macOS account; there is no separate multiuser login, application-layer evidence encryption or cryptographically tamper-proof audit. Unlink/SQLite deletion does not guarantee physical SSD erasure.

Actual sound tests prove Ready→playing→stopped API behavior, not that a person heard a warning. Desktop output is optional/platform-dependent and submitted notification requests are not falsely recorded as confirmed delivery. No email, mobile recipient, emergency service or other external notification was contacted.
