**Date:** 2026-10-27. **Canonical project:** `/Users/prabhuram04yahoo.com/Documents/Bhupesh/Projects/Project Sentinal`.

**Outcome:** dynamic user-video imports, local-file playback controls, isolated live camera capture and network-feed integration are implemented and exercised with real inference. The original V0.1 report is preserved in `docs/verification/V0.1.0_VERIFICATION_REPORT.md`.

## What changed

- Any decodable local video can be imported through the file picker or drag/drop at runtime. Copying/hash/decoder checks run in a background worker with progress and cancellation. Imported files stay in `data/videos`; original files remain intact. Full-hash deduplication, atomic publication, reserved-filename protection and disk-space/error cleanup are implemented.
- A new video can be imported while monitoring; the app stops the old source, starts a fresh tracking session, and reuses its loaded model. There is no application rebuild or fixed sample-file dependency.
- File playback supports pause/resume and seek. Seeking resets tracker state/session UUID; decoder timestamps are preferred, with average-FPS fallback where needed. Inference size is adjustable during monitoring.
- Camera and network decoding run in an isolated process with a fixed shared-memory latest-frame slot. Superseded frames are counted; stale/disconnected sources report errors. Driver shutdown is bounded, and capture/shared-memory resources are released.
- RTSP/RTSPS/HTTP/HTTPS endpoints have explicit connection controls and masked in-memory credentials. Display labels/errors omit URL credentials, paths and queries. Established stream loss receives bounded retries; reconnects create fresh sessions and clear stale observations.
- Project storage remains local to the canonical folder. The former workspace is empty. No new runtime dependency or paid/cloud inference service was added.

## Actual camera measurements

The new camera GUI test used five explicit Start/Stop cycles with six distinct displayed frames each. It confirmed child-process capture, fresh frame age/drop measurements, model reuse, unique sessions, resource release and worker shutdown. Stops measured **62–89 ms**. Short-cycle throughput varied, so it is not used as a sustained FPS claim.

A separate headless VisionPipeline observation then monitored the built-in camera for **60.026 s**, using MPS and 640×480 returned frames. It processed **1,409 frames**, or **23.47 wall FPS including startup**. After the first 10 s, measured throughput was **23.99 FPS** across 1,200 frames. Warm mean vision latency was **17.11 ms** (maximum 32.59 ms); mean local frame age at completed analysis was **20.38 ms** (maximum 38.74 ms).

The newest-frame reader counted **31 superseded capture frames during cold startup**; that count did not grow after 15 s. Cold first-inference latency reached about 1.37 s, which remains visible in the raw evidence. Stopping the observation took **43.9 ms**. Child process, source handles and shared-memory name were released.

Twelve bounded five-second memory samples showed warm parent RSS changing from **532.73 MB to 524.35 MB**, child RSS from **92.44 MB to 75.33 MB**, with reported MPS current/driver allocations unchanged. These are process measurements for this headless one-minute observation, not a full desktop memory benchmark or proof of indefinite leak freedom/thermal stability. Observed camera frames contained zero model detections; positive person detection was separately demonstrated on real recorded footage. No physical-person count or bag accuracy was inferred from the camera observation.

No camera frames, camera screenshots, video/audio recordings, bounding boxes or individual IDs were saved by the camera verifiers. Detection metadata stayed disabled and its database fingerprint remained unchanged in those runs.

## Test scope and limits

The automated suite covers configuration/coordinate contracts, output normalization, counts, storage/retention/failure handling, model/backend fallbacks, file/camera lifecycle, URL validation/redaction, real decoder seek, fixed-slot freshness/drop behavior, partial allocation/unlink cleanup, a deliberately hung simulated driver, worker pause/seek/reconnect/resolution/command coalescing, dynamic GUI import/drop/cancel/close behavior, and actual recorded-video inference.

Mocks and small synthetic encoded clips are confined to identified component tests. They do not establish camera access or model accuracy. The native camera and network reports establish those separate executed paths. The model remains official local YOLO11n with ByteTrack, using the same verified weights/checksum and license as V0.1; no new training or specialized detection capability was introduced.

Required model labels are person, backpack, handbag and suitcase. Previous bag examples and misses remain valid and preserved: not all annotated bags were detected, one handbag localization fell just below the example IoU cutoff, and moving pedestrian tracks showed visibility gaps. Selected successful still images are not a calibrated unseen-data accuracy estimate. Moving-bag identity correctness, multiple bags through occlusion, physical camera unplug/replug, external camera formats/authentication, multi-hour operation and cross-camera identity are still pending field acceptance. No unattended-bag, ownership, intent, violence or autonomous alert logic is implemented.

Live frame age measures local decoded-frame read through completed analysis; it cannot reveal upstream encoder/network buffering or GUI paint delay. Live images above a 1920-pixel longer edge are resized before the packet, and coordinates refer to that returned frame. File dimensions remain decoded source dimensions. Codec support is determined by the installed decoder; arbitrary file selection does not guarantee every possible format. Imported files are copied intact, including any pre-existing audio, while SENTINAL captures no microphone/audio stream.

## How to use the delivered input flows

Open `launch.command`. Import or drop your own video at any time; choose Camera and Start for the built-in feed; or select Network camera, enter the actual video endpoint and credentials, then Start. Nothing activates a camera or contacts a remote feed before a user action. Metadata is unchecked at launch. See `docs/REAL_INPUTS.md`, README.md and `docs/ON_DEVICE_ACCEPTANCE.md` for operation and remaining field checks.
